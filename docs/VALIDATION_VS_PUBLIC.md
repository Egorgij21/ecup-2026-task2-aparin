# Связь локальной валидации и паблика — как читать числа

Оплачено несколькими сабмитами. Кратко: **локальный OOF — несмещённая оценка обобщения,
паблик — один шумный отсчёт. Но две категории ведут себя ПРОТИВОПОЛОЖНО, и это решает всё.**

## 1. Что такое каждое число

* **Локальный OOF** (`exp/folds.py`, 5 фолдов ПО СЕМЬЯМ): каждую строку скорит модель,
  которая её не видела (held-out). Проверено программно: OOF фолда k содержит РОВНО
  строки с `make_folds()==k`, без пересечений, без NaN, полное покрытие 12971 строки.
  Утечки нет — значит это честная оценка того, как решение сработает на новых данных.
* **Паблик** — единичный прогон на неизвестной доле теста. Один отсчёт случайной величины.

## 2. Две категории — разный режим шума. ГЛАВНОЕ

| | локально позитивов | на паблике ~ | локальный CI (bootstrap) | паблик σ |
|---|---|---|---|---|
| **БАД** | 5564 | ~685 | **±0.009** | мал (точен) |
| **ФЛАМ** | 198 в 87 семьях | ~24 | **±0.063** | ~0.10 |

* **БАД: локаль ≈ паблик, оба точные.** Большой класс → малая дисперсия. Паблик-БАД
  совпал с локальным OOF уже 4 раза (v13, v16, v17, v20). **Локальному OOF по БАД можно
  доверять как предсказанию паблика.**
* **ФЛАМ: локаль шумная (±0.063), паблик ещё шумнее (σ≈0.10).** 87 семей позитивов →
  огромная дисперсия. Локальный прирост < ~0.06 неразличим; на паблике < ~0.012 неразличим.
  **v21 (флам-бленд) = v20 в точности на паблике** — прямое подтверждение: наши изменения
  на флам паблик не видит.

## 3. Метрика = среднее(F1_флам, F1_БАД) → паблик двигает БАД

Паблик-скор = 0.5·(шумный флам) + 0.5·(точный БАД). Флам-часть на паблике — шум, поэтому
ДВИЖЕНИЕ паблика определяется БАД. Отсюда факт: весь реальный прогресс (v8→v20) — по БАД,
а флам-изменения проявляются как шум/ноль (v21=v20, v22/v23 весь плюс от БАД).

## 4. Почему сравниваем при ФИКСИРОВАННОМ пороге, а не вложенном

Сабмит применяет ОДИН зашитый порог. Вложенный порог мерит ДВА свойства сразу: качество
скора И стабильность выбора порога. Сравнение способов бленда/объединения обязано идти
при фикс. пороге — иначе вложенная процедура обманывает (оплачено 3 раза: геом. среднее
v11 −0.015, lr 2e-4, вес БАД v19). См. CLAUDE.md §7–8.

## 5. Асимметрия «нестед vs all-data» (почему паблик обычно НЕ хуже локали)

Локальный OOF-ансамбль обучен на 4 фолдах (нестед, чтобы не было утечки). Сабмит-ансамбль
обучен на ВСЕХ данных. Значит сабмит видит больше данных → на паблике должен быть НЕ хуже
локального OOF. **Локальный OOF — консервативная нижняя оценка сабмита.** Поэтому локальный
БАД 0.9487 у v20 → сильный паблик-БАД.

## 6. Практическое правило принятия решений

* **Изменение по БАД** → доверяем локальному OOF при фикс. пороге (различимо при ±0.009).
  Бьёт v20 больше CI и паблик подтвердил → реально.
* **Изменение по флам** → локально НЕ подтвердить (±0.063). Только диверсификация; никогда
  не ждать от флам-изменения измеримого паблик-прироста.
* **Любой суммарный прирост < 0.012** — ниже разрешения паблика; паблик его не подтвердит,
  решать только по локальному БАД-OOF (если это БАД) или не решать вовсе (если флам).

## 7. Единственная доверенная линейка

`exp/eval_oof_tagged.py <тег>` (полный OOF, конфигурация сабмита) и
`exp/eval_fold_fixed.py <фолд> <теги>` (фикс. порог). Не заводить новых способов мерить
метрику — раньше одна конфигурация давала 0.9002 в одном скрипте и 0.9006 в другом.

# Контроль качества карточек — воспроизведение решения

Бинарная классификация карточек товаров по двум категориям — «БАД» и
«Легковоспламеняющиеся» — плюс генерация текстового комментария к вердикту.
Метрика = среднее F1 по двум категориям (комментарий в метрику не входит, но обязан
быть 50–300 символов, иначе строка бракуется).

В архиве — только КОД и инструкция. Исходные данные соревнования, веса адаптеров,
кэш моделей и промежуточные результаты НЕ включены (их нужно получить/пересчитать).

---

## 1. Что за решение (финалы v22 и v23)

```
карточка = name + description + изображения товара
   │
   ├─ ТЕКСТОВЫЙ АНСАМБЛЬ (обе категории):
   │    TF-IDF(слова 1-2, name×3) + регулярки из правил ТЗ
   │    + 5 признаков zero-shot Qwen3.5-4B  ──► LogReg ─► p_ансамбль
   │
   ├─ ФЛАМ: 0.5·p_ансамбль + 0.5·среднее(текстовые LoRA), порог 0.45
   │        v22: 2 адаптера (gemma-текст + Qwen-текст, декорреляция баз)
   │        v23: + 3-й адаптер (gemma-текст с прицельным промптом «flamtypes»)
   │
   └─ БАД:  0.5·p_ансамбль + 0.5·среднее(3 LoRA С КАРТИНКАМИ), порог 0.47
            три gemma-адаптера на изображениях с РАЗНЫМИ промптами:
            badimg + noexcl + sportbad (бленд промптов)
   │
   └─► <комментарий>ШАБЛОН<вердикт>{бан|не бан}
```

Ключевые инженерные решения:
* **LoRA мержится вручную** на инференсе (`W += (alpha/r)·B·A`, накопление float32) —
  в образе для сабмита нет `peft`. См. `submit_finals/*/src/lora.py`.
* **Никакой распиковки sklearn** — ансамбль экспортируется словарём (idf + коэффициенты),
  TF-IDF считается вручную. Версия sklearn на инференсе неизвестна.
* **`logits_to_keep=1`** — иначе тензор `batch × seq × vocab` роняет по OOM.
* **Изображения** рядом с тестовым csv: `<csv>/../images/<id>/*.jpg`.
* **Никаких молчаливых откатов**: нет модели/адаптера/CUDA — падаем в `preflight()`.

## 2. Окружение

* Python 3.11. Пакеты инференса: `torch`, `transformers`, `PIL`, `numpy`, `pandas`,
  `sklearn`. Пакеты обучения дополнительно: `peft`, `safetensors`, `scipy`.
* Базовые модели (HuggingFace): `google/gemma-4-E4B-it`, `Qwen/Qwen3.5-4B`.
* GPU (обучение мультимодальных адаптеров — на A100/H100-класс).
* Пути в коде указывают на корень проекта `/workspace/counter` — положите код туда
  или замените этот префикс на свой корень (переменная `ROOT` в скриптах `exp/`).
  Кэш моделей — через `HF_HOME`. Для инференса путь к моделям — через
  `SHARED_MODELS_PATH` (симлинки на снапшоты HF).

## 3. Что положить самому (НЕ в архиве)

```
/workspace/counter/data/data.csv              # обучающая выборка соревнования
/workspace/counter/data/images/<id>/*.jpg     # изображения товаров
<HF_HOME>/…                                    # снапшоты gemma-4-E4B-it, Qwen3.5-4B
```
Формат `data.csv`: колонки `id, name, description, category, label`
(`category ∈ {БАД, Легковоспламеняющиеся}`, `label ∈ {0,1}`).

## 4. Конвейер воспроизведения

Все команды — из каталога `exp/`. Python — ваш venv.

**0. Фолды.** Семейная 5-фолд нарезка (`exp/folds.py`) считается на лету всеми
скриптами. Резать по семьям обязательно: near-duplicates в данных иначе завышают CV.

**1. Zero-shot признаки для ансамбля.**
```
CUDA_VISIBLE_DEVICES=0 python llm_zeroshot.py        # -> exp/llm_scores.parquet
```

**2. Артефакты текстового ансамбля** (idf + коэффициенты LogReg, словари):
```
python train_export_v3.py            # -> artifacts/{meta.json,model_bad.npz,
                                     #     model_flam.npz,vocab_bad.json,vocab_flam.json}
```

**3. LoRA-адаптеры НА ВСЕХ ДАННЫХ** (`exp/lora_train.py`, аргументы: `<фолд|all> <эпох>`;
ручки — через переменные окружения). Точные команды продублированы в `exp/queue_*.sh`.
Целевые модули LoRA задаются `LORA_TARGETS` (regex; для мультимодального Qwen включает
`linear_attn`, см. `queue_qwen_mm.sh`).

Общий шаблон (gemma, текст):
```
GT='model\.language_model\.layers\.\d+\.(self_attn\.[qkvo]_proj|mlp\.(gate|up|down)_proj)'
CUDA_VISIBLE_DEVICES=0 LORA_TAG="<тег>" LORA_IMAGES=0 PROMPT_VARIANT="<вариант>" \
  LORA_BASE_MODEL=google/gemma-4-E4B-it LORA_TARGETS="$GT" python lora_train.py all 2
```

Адаптеры, нужные финалам (все `all`-data):

| тег | база | картинки | PROMPT_VARIANT | в сабмите → папка |
|---|---|---|---|---|
| `_gemma` | gemma-4-E4B | нет | (пусто) | `lora_adapter` (флам) |
| `` (пусто) | Qwen3.5-4B | нет | (пусто) | `lora_adapter2` (флам) |
| `_flamtypesall` | gemma-4-E4B | нет | `flamtypes` | `lora_adapter3` (флам, **только v23**) |
| `_mmtpall` | gemma-4-E4B | 1 | `badimg` | `lora_adapter_bad` (БАД) |
| `_noexclall` | gemma-4-E4B | 1 | `noexcl` | `lora_adapter_bad2` (БАД) |
| `_sportall` | gemma-4-E4B | 1 | `sportbad` | `lora_adapter_bad3` (БАД) |

Мультимодальные (картинки) обучаются с `LORA_IMAGES=1 LORA_MAX_PIXELS=261120
LORA_MAXLEN=1600 LORA_BS=2 LORA_ACC=16` — см. `queue_bad_prompt.sh`.
Варианты промптов (`badimg/noexcl/sportbad/flamtypes`) определены в `exp/deps/prompts.py`.

**4. Сборка сабмита.** Скопировать в папку финала (`submit_finals/v22` или `v23`):
* `adapter_config.json` + `adapter_model.safetensors` каждого адаптера в его папку
  (`lora_adapter`, `lora_adapter2`, [`lora_adapter3`], `lora_adapter_bad`,
  `lora_adapter_bad2`, `lora_adapter_bad3`) по таблице выше;
* артефакты ансамбля из шага 2 в `artifacts/`.
Промпт КАЖДОГО адаптера на прогоне обязан совпадать с обучающим — это уже зашито в
`run.py` (`build_messages_*` вызываются попарно с нужным адаптером).

**5. Дымовой прогон и упаковка.**
```
SHARED_MODELS_PATH=<симлинки_на_модели> \
  python run.py -i <8_строк>.csv -o out.csv    # проверить формат строки регуляркой
zip -r submit.zip run.py src artifacts lora_adapter*   # упаковать
```
Формат строки: `<комментарий>ТЕКСТ<вердикт>{бан|не бан}`, комментарий 50–300 символов,
одна строка на id. Одна невалидная строка бракует всё решение.

---

## 5. Валидация — самое важное

* **Фолды по СЕМЬЯМ** (`exp/folds.py`): связные компоненты по косинусу char-нграмм
  нормализованного названия. Группировка по точному тексту завышала CV на ~0.10.
* **Сравнение — только при ФИКСИРОВАННОМ пороге**, как работает сабмит. Подбор порога
  на тех же данных систематически обманывал.
* **Решает только полный OOF на 5 фолдах.** Один фолд шумит на ±7 пунктов PR от сида.
* Канонический замер: `exp/eval_oof_tagged.py <тег>`, `exp/eval_fold_fixed.py <фолд> <теги>`.
* Связь локальной валидации и паблика (какая категория чем меряется) — `docs/VALIDATION_VS_PUBLIC.md`.

## 6. Оглавление кода

| путь | назначение |
|---|---|
| `exp/folds.py` | нарезка по семьям — фундамент валидации |
| `exp/rule_features.py` | признаки из правил категорий |
| `exp/deps/prompts.py` | промпты и их варианты (badimg/noexcl/sportbad/flamtypes) |
| `exp/deps/imgutil.py` | единый загрузчик картинок (в т.ч. тайлинг) |
| `exp/llm_zeroshot.py` | zero-shot признаки Qwen для ансамбля |
| `exp/train_export_v3.py` | экспорт артефактов текстового ансамбля |
| `exp/lora_train.py` | обучение LoRA (текст и мультимодальное, ручки через env) |
| `exp/lora_infer.py` | скоринг адаптеров (в т.ч. мультимодальный) |
| `exp/eval_oof_tagged.py`, `exp/eval_fold_fixed.py` | канонические замеры метрики |
| `exp/queue_*.sh` | точные команды обучения адаптеров под каждый эксперимент |
| `submit_finals/v22`, `submit_finals/v23` | код двух финалов (run.py + src/, без весов) |

Прочие скрипты `exp/*.py` — исследовательские замеры и разборы (декорреляция баз/
промптов/модальностей, стекинг, bootstrap-CI шумового пола и т.д.), для полноты.
